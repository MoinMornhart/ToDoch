# ADR 0002 – Content Security Policy ohne Nonces

**Status:** angenommen (v0.0.1)

## Kontext

Gefordert ist eine strenge CSP ohne `'unsafe-inline'`. Nonces setzen voraus, dass jede HTML-Antwort
serverseitig erzeugt wird. ToDoch liefert die Oberfläche aber als statische Dateien über Caddy aus
(SPA), damit kein Node-Prozess im Betrieb läuft.

## Entscheidung

- Die CSP verbietet Inline-Skripte und Inline-Styles vollständig:
  `default-src 'self'; script-src 'self'; style-src 'self'; …; frame-ancestors 'none'`.
- SvelteKits einziges Inline-Startskript wird nach dem Build in eine eigene Datei ausgelagert
  (`scripts/externalize-inline-scripts.mjs`). Der Build bricht ab, falls doch ein Inline-Skript
  oder ein `style`-Attribut im HTML übrig bleibt.
- Das `style`-Attribut des Screenreader-Ansagers (`#svelte-announcer`) wird beim Build entfernt,
  dieselben Regeln stehen in `app.css`.
- Komponenten verwenden keine statischen `style`-Attribute. Dynamische Werte (z. B. Bereichsfarben)
  werden per `style:`-Direktive über das CSSOM gesetzt – das erlaubt die CSP.
- Die E2E-Tests laufen gegen den Produktions-Build mit derselben CSP und schlagen bei jedem vom
  Browser gemeldeten Verstoß fehl.

## Folgen

Strengere Richtlinie als mit Nonces (kein Inline-Code überhaupt). Ein SvelteKit-Update, das das
Startskript anders ausgibt, fällt sofort im Build oder in den E2E-Tests auf.
