Security

ToDoch follows one principle: security before convenience – secure defaults, nothing security-relevant can be switched off. The full threat model is in docs/SECURITY.md (German).

Sign-in

  • Passkeys (WebAuthn) with Face ID, Touch ID, Windows Hello or a security key – without a username, with one-time challenges, origin and domain checks and detection of cloned keys.
  • Passwords with Argon2id, at least 12 characters, checked against an offline list of stolen passwords.
  • Two-factor with an authenticator app (TOTP) and ten recovery codes – every code works only once, failed attempts are limited.
  • Lockout with increasing delay after failed attempts, setup only with a one-time code.

Sessions

Stored server-side (as a hash only), individually revocable, with idle and absolute timeouts. The device overview shows whether you signed in with a passkey or a password; “Sign out everywhere” ends them all.

In the browser

A strict Content Security Policy without unsafe-inline, double-submit CSRF protection with origin checks, HSTS, X-Frame-Options, Referrer-Policy: no-referrer and a tight Permissions-Policy. The tests fail as soon as the browser reports a CSP violation.

Data

  • Credentials such as subscription addresses with tokens are stored encrypted with AES-256-GCM; keys can be rotated.
  • Added calendars are only fetched from checked addresses: no loopback, no cloud metadata, home network for admins only, even after redirects (SSRF protection).
  • Mailboxes only over encrypted connections (SSL/TLS or STARTTLS with certificate checks), with the same address checks and pinned to the checked IP. ToDoch only reads along, the password is stored encrypted, and emails are shown as plain text only – never HTML, images or tracking.
  • Every object belongs to an area; other people's objects behave as if they didn't exist (404). Automated tests check every route for this.
  • An audit log for sign-ins and security-relevant changes – append-only, enforced by database triggers.

Operations

Non-root, read-only containers with all capabilities dropped; database and Redis without open ports in an internal network. No telemetry, no CDNs, no requests to third parties – except the calendars you add yourself and the browsers' push services.
